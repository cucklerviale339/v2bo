# 订阅防护升级说明

本功能位于管理后台「设置 → 订阅防护」（`/config/subscribe-guard`），不再嵌在订阅统计页内。升级后默认关闭拦截，不自动导入参考项目的黑名单，不封禁已有用户，不重置订阅 Token。原有节点地址、额外节点、内鬼管理以及低流量统计继续使用现有逻辑。

## 与参考项目的对应关系

- 提供请求总览、Top IP / Token / UA、用户 ID / 邮箱查询、按 UA 搜索关联用户及匹配记录、按请求数或 IP 数排行、账号详情及封禁/恢复、最近防护记录和快捷封 IP / Token / UA。
- IP/UA 黑白名单采用独立多行输入，支持快捷添加规则；保留到期时间、备注及用户订阅限制。快捷操作默认有效 24 小时，不自动开启拦截，不连带提交未保存设置。
- 敏感访问功能已移除：不展示敏感访问排行、明细和设置，不开放对应统计接口。旧节点敏感上报接口返回 410，兼容配置明确下发关闭和空规则，不再采集。历史表保留，不主动删除旧数据。
- UA 黑白名单每行一个关键词，大小写不敏感，白名单命中后跳过 UA 拦截。Token 黑名单每行输入一个原始订阅 Token，精确匹配且区分大小写，可保存后再次编辑。保留观察模式和旧项目默认关闭拦截；入口分组仍使用实际内鬼覆盖规则。
- 「封禁账号」使用现有用户封禁逻辑，会清理会话并影响节点使用；「仅限制订阅」只限制节点获取。订阅防护页面不能封禁管理员、员工或当前管理员自己。
- 用户详情仅返回白名单账号字段，不返回密码、UUID、Token、订阅 URL 或额外节点凭据。提前拦截通过只读 Token 验证关联用户，不消费一次性 Token、不写入定时 Token 缓存；无效或过期 Token、查询超时显示“未识别用户”。

## 常见爬虫 UA

独立开关控制 curl、wget、python、Go-http-client、Java/、Postman、okhttp、httpclient、node-fetch、axios 等关键词的自动拦截，匹配方式与参考项目一致。正式拦截模式和该开关均开启时执行；UA/IP 白名单豁免 UA 拦截。关闭开关不撤销其他黑名单。

「常见爬虫 UA 触发用户」按用户聚合触发次数、爬虫规则拦截数、全部规则拦截数、白名单命中数、IP/UA 数及最近时间；可查看用户详情和分页请求明细（邮箱、ID、IP、UA、时间和实际处理结果）。关闭防护或关闭该开关时仍记录命中，不自动封禁账号。历史只有已明确记录为爬虫拦截的事件可纳入，不伪造旧记录的匹配状态。

## 数据与兼容性

- 启动时幂等创建 `v2_subscribe_guard_config`、`v2_subscribe_guard_event`、`v2_subscribe_guard_rate`、`v2_subscribe_guard_audit` 四张表。
- 不修改用户表和旧 `v2_subscribe_access_log` 表，不扫描重写历史记录。新事件表幂等增加爬虫识别与白名单标记字段。旧统计继续展示原有数据；新防护记录在关闭、观察和拦截模式均产生，关闭模式只识别并记录，不执行拦截或限流。
- PostgreSQL 账号需有创建表的权限。初始化失败时订阅继续工作，防护管理接口返回未就绪，服务日志提示错误。
- 不需要 Redis、新环境变量或手动执行 SQL。旧版本可继续使用升级后的数据库；回退代码时保留新表即可。

## 老项目升级

先备份实际使用的数据库、`.env.go`、`config/admin.json` 以及自定义订阅模板。使用已包含本改动的版本，按项目正常流程执行 `./scripts/appctl update`，不要执行 `install`、`seed-demo` 或清空数据库。

确认健康检查、现有订阅、节点地址及内鬼规则下发正常后，在「设置 → 订阅防护」添加少量规则，保存为「仅观察」。观察模式记录访问及匹配结果但不拦截，原订阅认证只执行一次，兼容一次性和定时 Token。

检查命中请求的用户、UA、IP 与状态码，确认不会影响正常客户端，再保存为「正式拦截」。建议初期规则设置 24 小时到期；IP/Token 限流、空 UA 和脚本 UA 拦截默认均关闭。

## 规则语义

- Token 黑名单限制实际提交的具体 Token。可编辑列表在数据库中使用基于 `APP_KEY` 的 AES-GCM 加密；仅管理员配置接口解密返回，请通过 HTTPS 管理。事件和配置历史仍只留 HMAC-SHA256 指纹，不存储含 Token 的订阅路径。历史指纹规则继续生效，不可逆恢复；更换 `APP_KEY` 会导致新列表无法解密且影响原认证，日常升级不要更换。
- 用户订阅限制按 ID 生效，覆盖一次性或定时 Token；只限制获取节点，不封禁账号，不主动断开已经连接的设备。
- IP 白名单跳过 IP 黑名单、UA 检查和 IP 限流；不绕过 Token 黑名单、Token 限流或用户订阅限制。
- UA 白名单仅跳过 UA 检查。UA 关键词不区分大小写，不能当作可信身份凭证；客户端可以自行设置 UA。
- IP 支持 IPv4、IPv6 和 CIDR。规则支持到期时间，移除后保存即可撤销。配置使用版本校验，避免多个管理员互相覆盖；操作记录保存管理员 ID 和变更版本。
- 保护 `/api/v1/client/subscribe` 及自定义/路径 Token 订阅、App `getConfig`、`entry-provider`、用户 `runtime-profile` 与 `server/fetch`。节点服务端拉取用户和上报流量接口不属于客户端订阅入口。

## 真实 IP 与限流

订阅统计与防护记录使用同一套客户端 IP 解析。`trusted_proxies` 未配置或为空（包括旧版本保存的空列表）时，默认仅信任本机反向代理 `127.0.0.1/32` 和 `::1/128`；其他直连来源只使用 TCP 连接地址，不接受其自行提交的转发头。显式配置非空列表时，以该列表为准，不额外加入默认代理。

可信代理的 `X-Forwarded-For` 按完整链从右向左剥离可信代理，使用最近的非可信地址，最多接受 32 跳。只有未提供 XFF 时，才使用合法且唯一的 `X-Real-IP`；非法或过长的 XFF 不回退到其他头。忽略单独的 `CF-Connecting-IP`、`True-Client-IP`，避免客户端伪造。Nginx 至少需要：

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

Docker、远程代理或 CDN 不在默认信任范围内。需要在订阅防护配置 API 的 `trusted_proxies` 中明确配置实际代理 CIDR（保留完整策略和版本号），或在 Nginx 正确配置限定可信来源的 real_ip 处理并覆盖传递解析后的客户端地址；不要直接信任所有来源、全部私网或外部提交的 CDN 头。没有携带转发头的本机请求仍显示 `127.0.0.1`。修复仅影响后续请求，历史误记的 IP 无法从现有记录还原，不自动改写。

IP 和 Token 每分钟限额均为独立开关，0 代表关闭。使用 PostgreSQL 原子计数，多进程共享，重启不重置同一分钟的限额；保存新配置会使用新计数桶。采用固定分钟窗口，分钟交界可能出现两段额度连续用完的突发。不要用过低 IP 限额限制共享 NAT 出口。

## 失败行为与应急恢复

风控配置和计数访问有超时，读取失败时优先保证订阅继续工作，服务日志会限频提示。配置跨进程最多缓存 2 秒。事件写入通过有界队列执行，不阻塞订阅；队列繁忙或写入失败会丢弃风控事件，管理页面显示本进程丢失数量。这不是保证无损的审计日志。

请求记录保存实际 HTTP 状态码，无法识别用户的拦截也会展示。历史数据不会凭空补齐；只读识别失败或超过 200ms 时不改变拦截结果，保留 IP 和 UA 供排查。记录按设置保留天数，每分钟分批清理；配置操作历史单独保留。页面不再展示「最近配置操作」，也不再发起该面板的历史查询；后台审计写入和配置版本校验继续保留。

误拦截时，在后台将模式改为「关闭」并保存。也可以在 `/etc/forest/.env.go` 添加：

```dotenv
SUBSCRIBE_GUARD_FORCE_OFF=1
```

再执行 `systemctl restart forest`（独立测试部署服务名为 `forest-v2bo`）。紧急关闭优先于所有规则，也停止新防护事件记录，后台会显示提示。恢复时删除该环境变量并重启，再检查后台保存的模式。

回滚时恢复上一版代码和二进制，保留数据库与配置文件。新增表无需删除；服务仍按旧逻辑运行。仅当确实发生数据损坏时才需要按备份恢复数据库。
