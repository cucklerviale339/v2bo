# 谁是卧底

菜单位于备用监控的“故障转移”右侧。独立总开关默认关闭；默认同一原始组及所有后代 20 分钟最多处理一次，全局 60 分钟最多三次，可自定义。两个自动化系统共享成功操作计数，调查已接管的入口不会再由旧自动二分重复处理。

生效范围可选“全部入口组”（默认）或“仅多ID范围组”。后者按原始入口实际配置下发关系中含两个或以上 ID 范围判断，不按人数、具体 ID 数量或二分后地址判断；后代沿用原始入口资格。原始规则变化后按当前配置重新判断。范围同时约束新组接管及已有组自动处理；切换范围会重新观察，保留已生效的成员、地址、原始组和限频历史，范围外组保留监测与人工操作。

本模块自动组名使用“120分钟”“卧底”或“观察”，不附带 ID 范围，成员 ID 单独展示。“实锤内鬼”必须另有完整的入口本轮唯一拉取者故障证据，不能按分组人数生成。命名仅作用于本模块。

开启后，仅纳入已启用、有绑定探针、实际参与下发的入口。原始成员固定为当时配置范围内存在的账号，不按账号可用状态、套餐、节点权限等筛选；以后新增账号不会加入。额外节点不纳入调查。每个原始入口保留独立成员来源；观察组只在同一原始组内归并。

页面人数、ID 范围、编辑和自动处理均使用当前实际下发的具体成员。被其他规则接管的用户不改下发；成员为零隐藏。单人仍可正常观察、筛选和故障转移，只有已确认实锤、仅人工或固定策略阻止相应自动操作。提交前加锁重新核对地址和成员。

订阅、用户节点列表、App 配置和入口 provider 成功完整返回时，按响应中实际的连接地址记录用户每次获取该入口的时间（同一秒去重），同时保留首次下发时间，并绑定分组轮次。错误响应、304、模块、客户端格式省略的节点、SNI/WS Host 和额外节点不计入。此处“成功拉取”指服务器完整写出响应，无法证明客户端实际读取或连接成功。原访问日志不能用于回填这项证据。

自动处理分为三个独立事实：拉取观察轮次、本次入口故障、当前验证窗口。新入口须先检测正常，必须有同一配置下的真实成功检测，之后第一条失败结果是本次筛选截止时间 T。按探针最终 success 结果判断，不按 error 文本白名单；timeout、connect_error、dns_error、cancelled、未知或空报错均可交替出现，不会互相重置计时；成功才结束该故障。每探针、每配置版本、每轮次持久保存故障起点和成功基线，历史保留期清理不移动已建立的 T。收到的失败结果与没有收到检测结果分开处理：断报、过期、离线和配置变化不能伪装成入口持续失败。人工确认不能代替真实的成功基线。

自动执行要求全部绑定探针在线、最新结果为检测失败，并在当前验证窗口连续观察检测失败满十分钟。真实序号为纳秒时间戳，检查严格递增及时间间隔，不要求逐次加一；仍兼容连续整数序号。相邻完成和接收间隔均不得超过“检测间隔＋向上取整的 TCP 超时秒数＋5 秒调度余量”。缺失的检测时间不计为故障；纳秒序号的实际完成跨度和服务器接收跨度都须满足十分钟，不能用延迟上报凑满时长。自动限频、有效下发关系、健康同端口备用 IP、已确认实锤及人工策略限制和事务核对继续适用。

探针保留实际 TCP 拨号返回的错误，包含底层超时的包装错误报告 timeout；连接拒绝/不可达报告 connect_error，任务取消报告 cancelled，DNS 失败报告 dns_error。历史错误不回写、不猜测为超时。没有成功基线或普通断报使自动判定暂停时，原轮次拉取数据仍保留，管理员可直接“立即触发”。“确认入口”是另一个独立操作，会开始新轮次，不用于解锁旧轮次。

服务启动更新探针会话并写入可验证的衔接记录，旧会话上报仍拒绝。配置、探针集合及启用状态不变，且启动记录的时间位于相邻检测之间时，保留原 T 和拉取轮次；自动验证窗口从重启后的有效检测重新累计十分钟，正常对照也验证相同的当前窗口。升级停机时间不计为故障，也不永久阻断原故障。无启动记录的断报不伪装成升级；配置或探针重连变化仍重新观察。人工立即触发不依赖这些自动诊断条件。

自动筛选使用原首次检测失败的服务器接收时间 T，严格不包含该秒及之后的拉取。当前验证窗口内需有两个独立、持续正常的实际下发入口作为同探针对照；仅有一个其他实际监控入口时允许单个对照。相同解析 IP 不重复计数，其他组同时异常不直接否决。对照应在当前十分钟验证窗口前至少一分钟已正常，并持续至确认；升级空档不会永久阻断旧故障。自动处理遇到证据写入失败仍暂停；人工操作记录模式和截止时间来源，不把不完整证据伪装成自动确认。

| 拉取情况 | 自动行为 |
| --- | --- |
| 可按时间筛选 | 首次失败 T 前 `[T-7200秒, T)` 成功拉取的人进入“120分钟”；本轮拉取过但窗口内未拉取的人进入“卧底”；本轮未拉取的人进入“观察”。各个多人组领取不同新 IP；观察组可归并到同源健康观察入口。 |
| 全部拉取且同一时间类别 | 无法按时间缩小范围时，按实际成员 ID 排序二分；两半保留对应“120分钟”或“卧底”类别，使用独立入口。全部拉取但时间类别不同，优先按时间分组。 |
| 无人拉取 | 组名追加“无人拉取”，成员不变，换一个健康 IP；累计次数可见。 |
| 原有单人组 | 正常观察；健康入口在首次失败前仅此用户成功拉取、随后故障确认，才标记实锤。未拉取不能认定，发生故障仍分配健康入口。 |
| 二分或时间筛选产生单人 | 仍为“卧底”或“120分钟”，分配独立的新健康入口继续观察。1+1 二分不能把两人都标为实锤。 |
| 未拉取的单人观察组 | 保持“观察”，领取或合并到兼容健康观察入口；以新一轮拉取和故障证据判断，不永久豁免。 |

“120分钟”“卧底”“观察”均按每轮证据处理，不按人数永久排除。真正实锤保留故障入口，停止自动领 IP、细分和归并，只允许人工操作。两名以上用户拉取过同一入口，即使分别落在120分钟和更早两个单人分支，也都不构成唯一拉取者。

每轮重新筛选仅适用于“智能筛选”策略。管理员手工指定“仅故障转移”的观察组保持成员和策略，只换健康入口，不因拉取记录自动筛人，也不自动归并到智能筛选组；“固定下发”和“仅人工操作”仍保留各自含义。

升级撤销没有新版完整证据的历史实锤标签，并追加纠正审计，保留原始历史。不会在迁移事务直接改下发；原始审计明确、未编辑、成员仍存在、监控未删除且仍在原入口的自动单人组，可按原限频补发健康入口重新观察。已编辑的组保留人工策略与下发，不擅自恢复自动化。历史未拉取分支仍恢复“观察”。

领取备用 IP 要求同检测端口、未被其他规则/调查/监控占用、所有启用在线探针均有新鲜且连续两次成功的检测；检测端口不会变成订阅端口。全部组关系和地址切换在同一事务提交，提交前重新投影实际下发、核对容量及检测证据；IP 不足或冲突时不部分执行。

筛选、二分、无人拉取换 IP 及人工换地址产生的新入口，均继承来源入口在数据库中保存的检测端口、探针、间隔和超时，不读取浏览器的“上次输入端口”，也不回退为 443。修改某个子入口的检测端口后，其后代沿用该子入口的新配置。观察组仅归并到同一检测端口且确认健康的同源观察组；不同端口或备用池缺少同端口健康 IP 时等待，不降级使用其他端口。新入口从未确认正常时，不因持续失败继续领取 IP。

关闭总开关停止自动筛选、换 IP、归并和二分，保留已生效地址与成员；重新开启或改生效范围重新观察，只改限频不清空轮次。编辑支持组名、地址、策略和人工开关，只改名不清空证据。未确认的单人可自动观察，已确认实锤只能人工处理。

当前页面展示活动组，历史保留来源组、拉取/未拉取 ID、两半或归并目的组、入口和正常对照证据。每次成功下发的证据按分组、轮次、用户和秒去重；历史同时展示120分钟内和更早拉取人员；结束轮次的原始拉取证据保留 90 天，筛选审计不随监控历史清理而删除。

分组列表只显示当前仍向本组成员实际下发的入口；节点停用、规则停用或原地址改变后，失去下发关联的旧组不显示。该过滤不修改存储的成员、地址或下发规则；恢复实际下发关系后重新显示。入口异常或检测数据过期本身不会隐藏仍参与下发的分组。操作列固定在右侧，包含编辑、确认入口和立即触发。

在入口监控中删除入口时，该入口退出本模块：关联分组置为不参与，页面和筛选历史不再显示该入口，不再筛选、二分、自动换 IP 或应用调查下发覆盖；用户继续按原三层地址规则下发。不删除成员和证据记录，不改原节点及地址规则，其他未删除入口不受影响。升级时也排除此前已删除入口，总开关关闭时同样生效。仅关闭总开关或停用监控不等于删除，仍保留现有调查覆盖。

相关新增表使用 `v2_dispatch_*` 前缀，包括调查、稳定观察和筛选风险记录；不修改原三层规则、用户 Token、流量和订阅端口。功能开启后下发依赖这些新表，回滚前需停用并处理现有分组的地址承接，不能直接回滚代码而假设已有分配仍会生效。

升级到120分钟筛选时，旧版只保留首次拉取的证据不能补全重复拉取，因此仅对已有自动组开启一次新观察轮次，等待入口确认正常；保留成员、地址、开关、原始组关系和限频历史。之后重启不会重复重置。

数据库迁移在同一事务和数据库互斥锁内完成，避免管理接口、订阅和后台任务首次并发访问时同时创建表或索引。服务仅缓存成功的初始化；超时、取消或数据库暂时异常后允许重试。启动阶段提前执行迁移。从曾出现初始化失败的旧进程升级时，需要正常重启服务以清除旧进程缓存，不需要删除监控配置或历史。

“确认入口”和“立即触发”供自动组管理员使用，单人未确认组也可使用；已确认实锤、仅人工或固定策略不显示且后端拒绝。立即触发可按当前数据分组，但不能跳过实锤所需的真实健康基线、唯一拉取者、连续十分钟故障及正常对照验证。人工确认不伪造成功检测。

## 自动分离：3天稳定，再观察7天老实人

“稳定与老实人”默认关闭，不改变生产已有下发。两站各自独立。

1. 普通、卧底、观察、120分钟多人组中，实际成功拉取同一入口并有效观察满3天的具体用户进入“稳定组”，换到健康入口A。未满足条件的用户留在原组。
2. 用户成功收到A以后再有效观察7天，进入“老实人”，换到不同健康入口B。分配到A但没有成功拉取不开始个人的7天计时，最快总计10天。
3. 每个阶段复用站内同一健康入口，不为每批晋级额外领IP。各业务来源仍保留自己的固定用户清单、父子关系和下发条件，仅替换原本对应的节点地址，不覆盖其余节点。晋级允许源组与阶段入口使用不同检测端口，采用阶段入口自身配置。

正常进度和个人实际入口拉取记录持久保存。重启、改名、同IP合并、新人加入不会清零已有用户的有效证据；上报空档不累计，按个人与空档的交集暂停计时。短暂故障恢复后保留既有观察，确认的持续故障重置观察；实际入口或监控配置改变后重新观察。

首次升级按历史业务口径承接：当前实际组、当前入口自本轮开始后，未触发筛选、换址或人工编辑的时间视为正常观察，不要求已经过期的检测明细仍然存在。起点取当前轮次、总开关有效期、组创建时间以及本组最近筛选/换址/人工编辑等操作时间中的最晚值；个人晋级还必须有该边界之后、当前轮次中实际成功拉取该入口的记录，按个人拉取时间与组起点的较晚值累计。不改原轮次或下发规则，每组仅承接一次并留审计，标明依据为“未变更轮次与本轮成功拉取”；已有持久进度优先保留。升级后实时观察仍按检测检查点累计、扣除检测空档并处理确认故障，不把这项历史承接口径当作实时检测成功。

开启“稳定与老实人”不以开启时间截断历史进度；该开关仅控制晋级和阶段组自动处理，关闭时仍记录正常观察与实际拉取，重新开启可接续。总开关和生效范围的原有重置语义不变。旧版本仅保留约24小时检测明细不会再限制本次历史承接；旧轮次、旧入口、不再实际下发或已删除账号的拉取仍不作为新晋级依据。即使旧数据已满3天，也只可进入稳定组；七天阶段必须成功收到新入口A后另行累计，不跳级。新版本承接后用持久检查点累计，后续明细过期或正常重启不会清空已确认进度。

稳定组或老实人入口未确认正常、异常或报告过期时暂停接收晋级。稳定组故障回到筛选；老实人24小时首次确认故障整组换 IP，第二次多人组二分到不同入口继续筛选，单人不生成空分支。是否实锤始终单独核对完整证据。

备用池状态和测活规则不变。新建A/B阶段入口要求健康且未占用，允许使用备用池自身的检测端口；接收新成员时采用现有阶段入口的检测配置。普通故障转移、筛选及二分仍要求同检测端口，不使用浏览器的上次输入值，也不回退443。分配、成员迁移、实际下发投影、检测复核和审计在同一事务内完成。IP不足、并发变更或目标异常时整次延后，不部分迁移。关闭开关保留已经生效的地址与名单。

页面分为“入口分组”“稳定组”“老实人组”三个维护页签，后两类不再混在入口分组列表中；可按组名、入口、组ID或具体用户ID搜索。稳定组、老实人组的“编辑”沿用节点地址的维护方式，支持修改组名、下发地址和具体用户清单：邮箱搜索选人、直接输入ID、标签增删，不使用动态ID范围，至少保留一人。成员ID范围仅用于展示，不会把将来注册的新用户自动纳入。大名单的邮箱回显按每批100人顺序查询，避免超过查询上限。新增成员从其当前有效的业务分组迁入，沿用原节点下发范围；未纳入有效入口分组的账号不直接创建全节点覆盖。移出的成员恢复原业务规则下发，随后由普通观察接收，不直接回到阶段组。其他用户、节点端口及未管理的节点不变；旧全站组仍使用原“退出全站管理”，不混入业务范围编辑。

同入口编辑成员后开始新一轮故障筛选，保留留组成员已经累计的稳定观察天数；新加入或重新加入的成员清除旧的个人阶段计时，从成功拉取本次入口后重新计时。修改实际入口则清除本组个人计时、重新确认监控正常，检测端口、探针、间隔及超时继承当前入口。人数减至一人不会自动标记实锤或关闭自动化，仍按健康基线、实际拉取与确认故障的证据判断。组名修改或原名单原样保存不重置观察。入口与名单在同一事务核验实际下发、保存审计；无效用户、地址占用或版本冲突时整体回滚。

- **确认入口**：人工开始新轮次，下一秒起重新记录拉取和检测；旧轮次记录不进入新轮次筛选。成员和地址不变，不伪造探针成功。
- **立即触发**：人工执行当前轮次筛选、二分或无人拉取换 IP。独立于自动故障诊断，不受十分钟等待、旧检测空档、源入口是否恢复、正常对照及自动限频阻断。仍要求总开关开启、生效范围内、入口未删除、存在有效成员、足量健康未占用同端口备用 IP 和实际下发校验。优先使用本轮已记录故障起点；基线不完整则记录为首次观察失败；没有失败记录则以本次人工操作时点为快照截止时间。三种来源明确写入审计，沿用原轮次拉取记录和120分钟分类，不伪造故障起点、不重置观察。截止时间确定后本次事务固定使用，晚到检测不重新解释人工决策。成功计入后续自动限频；失败不提交分组、地址、IP 或成功审计。版本校验与数据库互斥避免重复或并发点击重复消耗 IP。

## 实锤证据与晋级限制

实锤同时要求：本轮入口实际检测健康；健康之后、首次失败 T 之前只有一个不同用户成功收到入口；入口在当前配置下连续检测失败满十分钟且同探针有独立正常对照。首次失败及之后拉取不计入。共享 IP 有组外下发或组外暴露、拉取记录不完整、人工执行时缺少完整故障证据，都不能生成实锤。

证明保存来源分组、轮次、入口、唯一用户、首次失败、探针与正常对照。提交前重新验证。检测端口继续继承源监控端口，不改为443或备用池其他端口。

首次故障后，“120分钟”与较早拉取的“卧底”分支均暂停个人晋级计时；未拉取者分到健康入口、实际成功拉取后可计时。后续某个独立分支确认故障，只有本次故障确认窗口内实际入口独立且健康的兄弟分支解除祖先事件的暂停，从解除时间与本次入口实际拉取时间的较晚值开始3天或7天计时，绝不补计此前暂停天数。故障分支本轮近期及较早拉取者继续暂停，明确未拉取者进入观察。已解除暂停的其他分支保持自己的有效进度，不因别处故障再次重置。

每次筛选建独立事件，按实际转移的具体用户与分支追踪，包含历史人工合并的来源组、晋级及手工转移。观察分支再次故障可以收窄祖先事件，但不会追认它过去未拉取的成员为候选。两条分支先后独立故障时，各自形成新事件，不能互相解除；三个原始业务组也不互相连带。未拉取、旧实锤标签或手工立即触发本身不等于确认故障，不能自动释放其他候选分支；无人拉取的故障不提供归因，不据此放行兄弟候选。共享入口、检测过期、异常或健康证据不完整的分支不算独立正常兄弟。

新事件持久记录故障确认结论与当时独立正常分组名单。旧事件仅用审计中保存的正常对照入口和当时入口关系核验，不臆造健康状态。升级回填与实时筛选共用同一计算器，重启不重置结论或解除时间。个人晋级以实际成功拉取、有效健康观察起点、风险解除时间三者最晚值计算，检测空档不计时。新版完整证据的实锤只解除其实际继承链对应事件，已确认用户始终禁止自动晋级。

已有历史筛选自动导入限制，旧的单人标签不作为事件解决证明。开启总开关及稳定与老实人功能后，后台核对当前实际下发的阶段成员：存在未解除筛选风险，或自动晋级时未满解除暂停后的对应观察天数，且最近一次加入由系统自动晋级完成的成员，移回独立的“待复核”组并分配健康未占用备用入口，检测端口采用所选备用IP的端口。保留每人的原业务下发条件，不回退旧地址或扩大到其他节点；纠正后仍受原筛选事件限制。最近一次明确由管理员加入的成员保留手工安排。无风险成员和保留的手工成员继续使用原入口，已有观察进度不重置。备用 IP 不足时显示“待纠正”，原下发不变；迁移、监控、个人进度清理和审计在同一事务中提交，失败整体回滚。重复运行不会再次迁移已纠正的成员。

历史分“故障与筛选”“稳定与老实人”“管理操作”，由后端按事件发生时的类型筛选、计数和分页。原始历史标签保留，并通过纠正记录说明旧实锤已撤销。

### 历史晋级名单独立复核

阶段晋级及历史纠正按原分组、原业务入口和具体用户核对迁移。同一个用户若在其他业务中仍使用原 IP，该关系保持原样，不再因原 IP 仍出现在该用户的下发列表而误判迁移失败。提交前同时核对所有有效分组归属、迁移用户的完整下发地址集合和其他用户的下发范围；不符合预期仍整体回滚。升级后，原先因该误判显示“纠正待重试”的组由后台自动重试，无需手工改生产数据。晋级与纠正可采用备用池自身的检测端口；普通故障转移、筛选及二分仍要求同检测端口。

纠正出来的具体成员在各站独立组成“待复核”组，名单冻结，分配本站健康未占用备用入口，检测端口采用所选备用IP的端口，沿用每人的原业务下发条件。明确手工保留的成员不迁移。备用IP不足时等待，名单、入口和审计不部分提交。

“待复核”成员持久禁止稳定组、老实人组自动晋级，无时间到期条件。正常3天、7天、更久，重启、改名、换入口、人工确认、无人拉取换IP、其他兄弟入口故障或手工立即触发但未确认故障，均不能解除此限制。限制跟随具体用户及其后续下发分支，不因换组绕过；待复核成员也不会自动与普通观察组合并。

仅本组后来出现完整确认的故障，且至少两个非空子分组的筛选或二分成功提交后，才解除该批实际参与成员的独立复核限制；等待补IP、提交回滚都不解除。然后按同一轮真实拉取证据继续判断：未拉取者从新健康入口实际拉取后重新观察；120分钟与更早拉取者继续暂停，等待后续追查收窄；满足实锤证明者仍仅人工处理。其他尚未解除的独立风险事件照常限制晋级。
