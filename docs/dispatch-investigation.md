# 谁是卧底

菜单位于备用监控的“故障转移”右侧。独立总开关默认关闭；默认同一原始组及所有后代 20 分钟最多处理一次，全局 60 分钟最多三次，可自定义。两个自动化系统共享成功操作计数，调查已接管的入口不会再由旧自动二分重复处理。

生效范围可选“全部入口组”（默认）或“仅多ID范围组”。后者按原始入口实际配置下发关系中含两个或以上 ID 范围判断，不按人数、具体 ID 数量或二分后地址判断；后代沿用原始入口资格。原始规则变化后按当前配置重新判断。范围同时约束新组接管及已有组自动处理；切换范围会重新观察，保留已生效的成员、地址、原始组和限频历史，范围外组保留监测与人工操作。

本模块自动组名使用“120分钟”“卧底”或“观察”，不附带 ID 范围；成员 ID 单独展示。自动产生的单人组仍命名“实锤内鬼”；无人拉取保留相应后缀。命名仅作用于本模块，不改入口监控、故障转移或其他节点/地址规则名称。

开启后，仅纳入已启用、有绑定探针、实际参与下发的入口。原始成员固定为当时配置范围内存在的账号，不按账号可用状态、套餐、节点权限等筛选；以后新增账号不会加入。额外节点不纳入调查。每个原始入口保留独立成员来源；观察组只在同一原始组内归并。

订阅、用户节点列表、App 配置和入口 provider 成功完整返回时，按响应中实际的连接地址记录用户每次获取该入口的时间（同一秒去重），同时保留首次下发时间，并绑定分组轮次。错误响应、304、模块、客户端格式省略的节点、SNI/WS Host 和额外节点不计入。此处“成功拉取”指服务器完整写出响应，无法证明客户端实际读取或连接成功。原访问日志不能用于回填这项证据。

新入口须先检测正常，再出现连续至少十分钟 TCP timeout；同一探针会话、配置和连续序号必须一致。恢复成功、断报、离线、过期、配置变更或非 timeout 错误均不能拼接成十分钟故障。全部绑定探针须在线、证据完整且一致超时。

拉取截止时间为本轮首次超时的服务器接收时间，严格不包含该秒及之后的拉取。故障窗口内需有两个独立、持续正常的实际下发入口作为同探针对照；总共仅有一个其他实际监控入口时允许单个对照。相同解析 IP 不重复计数；其他入口也有故障不直接否决，但不足稳定对照则等待。正常对照必须在故障前至少一分钟已正常，并持续到确认时。证据写入失败会阻止筛选，恢复后重新观察。

| 拉取情况 | 自动行为 |
| --- | --- |
| 可按时间筛选 | 首次失败 T 前 `[T-7200秒, T)` 成功拉取的人进入“120分钟”；本轮拉取过但窗口内未拉取的人进入“卧底”；本轮未拉取的人进入“观察”。各个多人组领取不同新 IP；观察组可归并到同源健康观察入口。 |
| 全部拉取且同一时间类别 | 无法按时间缩小范围时，按实际成员 ID 排序二分；两半保留对应“120分钟”或“卧底”类别，使用独立入口。全部拉取但时间类别不同，优先按时间分组。 |
| 无人拉取 | 组名追加“无人拉取”，成员不变，换一个健康 IP；累计次数可见。 |
| 原有单人组 | 不改名，跳过自动筛选、换 IP、二分和归并，仅人工操作。 |
| 自动产生单人组 | 改名“实锤内鬼”，保留原入口，不领取新 IP，仅人工操作；该名称是管理员指定的业务标签，筛选记录只证明时间相关性。 |

“120分钟”“卧底”“观察”三类组都执行同样的故障确认和筛选，不会作为永久排除名单。二分产生的两个当前候选组不自动归并；后续未拉取人员才进入观察组。单人组继续监控、保留证据，任何自动操作都不会改变其入口。

领取备用 IP 要求同检测端口、未被其他规则/调查/监控占用、所有启用在线探针均有新鲜且连续两次成功的检测；检测端口不会变成订阅端口。全部组关系和地址切换在同一事务提交，提交前重新投影实际下发、核对容量及检测证据；IP 不足或冲突时不部分执行。

筛选、二分、无人拉取换 IP 及人工换地址产生的新入口，均继承来源入口在数据库中保存的检测端口、探针、间隔和超时，不读取浏览器的“上次输入端口”，也不回退为 443。修改某个子入口的检测端口后，其后代沿用该子入口的新配置。观察组仅归并到同一检测端口且确认健康的同源观察组；不同端口或备用池缺少同端口健康 IP 时等待，不降级使用其他端口。新入口从未确认正常时，不因持续失败继续领取 IP。

关闭总开关停止筛选、自动换 IP、归并和二分，保留已经生效的下发地址与成员关系；不会回退到原入口。重新开启或修改设置重新观察。分组“编辑”可人工修改组名、独立下发地址和仅人工操作状态，带版本冲突保护；单人组不能恢复自动化。

当前页面展示活动组，历史保留来源组、拉取/未拉取 ID、两半或归并目的组、入口和正常对照证据。每次成功下发的证据按分组、轮次、用户和秒去重；历史同时展示120分钟内和更早拉取人员；结束轮次的原始拉取证据保留 90 天，筛选审计不随监控历史清理而删除。

在入口监控中删除入口时，该入口退出本模块：关联分组置为不参与，页面和筛选历史不再显示该入口，不再筛选、二分、自动换 IP 或应用调查下发覆盖；用户继续按原三层地址规则下发。不删除成员和证据记录，不改原节点及地址规则，其他未删除入口不受影响。升级时也排除此前已删除入口，总开关关闭时同样生效。仅关闭总开关或停用监控不等于删除，仍保留现有调查覆盖。

所有新增表使用 `v2_dispatch_investigation_*`，不修改原三层规则、用户 Token、流量和订阅端口。功能开启后下发依赖这些新表，回滚前需停用并处理现有分组的地址承接，不能直接回滚代码而假设已有分配仍会生效。

升级到120分钟筛选时，旧版只保留首次拉取的证据不能补全重复拉取，因此仅对已有自动组开启一次新观察轮次，等待入口确认正常；保留成员、地址、开关、原始组关系和限频历史。之后重启不会重复重置。

数据库迁移在同一事务和数据库互斥锁内完成，避免管理接口、订阅和后台任务首次并发访问时同时创建表或索引。服务仅缓存成功的初始化；超时、取消或数据库暂时异常后允许重试。启动阶段提前执行迁移。从曾出现初始化失败的旧进程升级时，需要正常重启服务以清除旧进程缓存，不需要删除监控配置或历史。
