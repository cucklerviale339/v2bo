# 分支观察、实锤与历史晋级纠正

## 分支计时规则

原组确认故障后，120分钟内拉取与更早拉取的分支均暂停个人晋级计时；本轮明确未拉取者，在新入口健康且实际成功拉取后开始观察。组本身健康多久，不等于个人有效观察多久。

其中一条分支再次确认故障，才解除该次祖先事件对健康兄弟分支的暂停。兄弟分支必须实际独立下发、有新鲜完整的健康对照、与故障入口不同且不解析到同一IP。计时从解除时刻和个人实际拉取时刻的较晚者开始，暂停期间不能补算。异常分支继续细分：拉取过的子分支继续暂停，明确未拉取者重新观察。

未发生新故障的已放行分支保留有效进度；之后自身确认故障则建立新的独立事件。不同分支、不同原始大组的事件互不抵消。观察分支后来故障，也可缩小祖先事件，但不会把曾经未拉取者补记成旧事件候选。

手工立即触发保留选定的拉取截止数据，但点击本身不构成故障确认。无人拉取、证据不完整、没有独立健康对照均不能放行兄弟分支。缺备用IP时先记录已确认故障，不因等待补IP反复重置兄弟组的放行时间。

个人满足3天有效观察后进入稳定组，换独立入口；实际拉取稳定入口后再累计7天，才能进入老实人组。服务检测空档不计时。

晋级到已有稳定组或老实人组时，原组与目标组的检测端口可以不同。目标入口按目标组自身的监控配置验证健康，接收成员后保留目标端口、原有成员和观察进度。晋级新建阶段入口、历史错误晋级回退新建待复核入口时，可从任意检测端口中选择健康未占用的备用IP，新监控采用所选备用IP的检测端口，仍继承来源探针绑定、检测间隔与超时。提交前重新核对所选IP、端口、启用和健康状态，变化则整笔回滚。实际节点业务端口不变。

上述跨端口例外仅用于晋级和历史晋级回退。正常细分、二分、无人拉取换IP、故障转移及老实人故障处理仍严格选择与故障入口检测端口一致的备用IP，并在提交前复核，不借用其他端口的测活结果。

历史晋级纠正等待备用IP或事务重试时，继续同步探针会话、累计有效正常观察并处理已确认故障；等待纠正的阶段暂不向下一阶段晋级，避免混合名单绕过纠正。页面分别显示阶段入口待确认、异常或缺少独立入口等具体原因。

## 实锤定义与历史标签

必须是入口先正常、本轮实际成功收到该入口的不同用户恰好1人，随后首次失败并连续确认故障，且有独立健康对照。单人分组、多人拉取后二分得到单人、旧组名均不是实锤证明。有效实锤仅解除其实际追查链的相关事件，其他独立事件保留。

以下旧单人标签来自多人拉取的筛选轮次，不能继续作为实锤结论：35站#46用户7468（原轮8人）、#88用户15978（10人）；39站#60用户3564（2人）、#61用户5339（2人）、#331用户6043（3人）、#334用户6751（5人）。

升级追加修正审计并撤销不满足新证明的标签，保留原始历史。满足完整审计条件、未手工编辑的系统误锁单人组恢复观察；明确人工策略继续保留。

## 验证边界

生产仅执行只读快照查询，没有纠正成员或改动入口。单元测试、PostgreSQL集成回放、并发检查及升级迁移验证在本地或测试环境进行。筛选历史分为筛选、稳定与老实人、管理操作。

“实锤内鬼”是按业务时间关联定义生成的标签，保存成功下发与入口检测事实，不代表攻击流量取证。
