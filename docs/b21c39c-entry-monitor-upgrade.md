# 从 b21c39c 升级入口监控

本次入口监控、备用 IP 池及近期检测功能直接基于 `b21c39ccc406b4bb18f5c8757aeb08a27f6b2397` 开发。参考项目用于检测流程设计；实际节点地址优先级仍使用本项目的内鬼管理、节点地址和节点管理规则。

## 兼容性

- 新增六张 `v2_dispatch_*` 表及对应索引，由面板启动时自动创建。不要求重新安装、导入安装 SQL 或重置旧表。用户、密码、订阅 Token、套餐、订单、节点地址及原 DNS 规则没有数据转换。
- 原 DNS 目标仍检测目标值，保留每个目标的自定义端口。入口和备用池的检测端口独立保存，不写入节点下发配置。
- 原探针 Token 和身份保留。旧探针在新面板上继续检测原 DNS；入口和备用池需要新版探针。
- 新增任务和结果使用独立接口、请求循环和重试队列。新目录或结果入库失败不会让原 DNS 任务接口依赖这些新功能。面板回退到旧版本时，新版探针停止不被支持的新增任务，原 DNS 继续使用原接口。
- 按用户最终选择，每个入口及备用池目标独立执行 TCP 检测，不使用串行或 64 并发名额。同一目标在完成一次检测并送入结果通道后等待配置间隔。保留每枚探针 1000 个新增目标的容量保护，以及有界结果队列和背压。
- 主动检测按钮和创建 API 已移除；近期检测保留历史查看、翻页和清理。新监控默认不启用，需要管理员选择入口和探针后开启。

## 升级步骤

1. 保存当前提交号，备份 PostgreSQL 数据库、实际使用的环境文件、`config/admin.json`、旧后端、前端及 `storage/probe/`。备份放在部署目录之外，并限制凭据文件的读取权限。
2. 在原部署目录确认 `git status --short`。如有生产本地修改，先保留并合并，避免覆盖环境配置。
3. 对使用项目默认部署脚本的实例执行 `./scripts/appctl update`。该命令拉取代码、运行原数据库更新、构建后端及 Linux amd64/arm64 探针、重启面板。自定义部署需完成相同操作，并使用本次前端构建产物。
4. 确认原管理员登录、用户订阅、节点地址、原 DNS 规则及探针心跳正常。新入口列表按配置 ID 归属展示，排除额外节点，不查询账号资格、节点权限或地址条件；它不是历史实际领取人数。
5. 在探针页面取得已有探针的安装命令，先在一台探针服务器重新执行，更新其运行二进制。面板的 `build-probe` 只更新下载文件，不会远程替换已经运行的探针。
6. 启用少量入口和备用 IP，核对健康、故障、过期及归属结果，再更新其余探针、扩大启用目标。检测大量目标时按探针主机资源配置间隔与超时。

不要在生产运行 `database/install.pgsql.sql`、重新安装、导入测试库或执行强制覆盖迁移。本次从 PostgreSQL 的 b21c39c 实例升级不需要这些操作。

## 重启和回退

每次面板进程初始化都会更新新增监控会话并清空新增当前测活状态，等待探针重新上报。配置和已完成的近期检测记录保留，旧会话结果不会恢复为健康。当前设计面向每个数据库一个面板实例；多个面板进程滚动启动会重复重置新增监控状态，部署前应据此安排。

如需回退，恢复保存的旧代码、后端、前端和探针下载文件并重启面板；必要时恢复探针运行二进制。新增表可保留，不需要删除。原 DNS 在重启或探针重新连接后可能重新预热，核对新鲜数据后再恢复观察。只有需要回退业务数据时才使用数据库备份，并明确备份之后的数据取舍。

## 验证范围

- `TestPostgresDispatchUpgradePreservesBaselineData` 使用与 b21c39c 相同的完整安装结构、旧 DNS 结构和已有数据，在独立测试 schema 中进行升级、配置入口、添加备用池及重复初始化。逐表比较原有数据，确认用户密码/Token、套餐、订阅日志、运行配置及旧 DNS 规则不变；验证四类用户的节点下发、原 DNS 任务和探针 Token 保持兼容。
- PostgreSQL 生命周期测试覆盖配置版本、重新连接会话、探针撤销、旧结果拒绝、故障删除重判、并发引用写入和容量超限回滚。故障注入验证新增表不可用时原 DNS 心跳仍可提交。
- 探针测试覆盖新增通道故障、面板回退和 DNS 上报隔离；70 个混合目标同时开始检测，验证已移除此前并发名额，取消后任务全部退出。
- 前端类型检查、生产构建及 Go 静态检查；Linux 后端和两种架构探针构建；测试服务器真实 TCP 成功/失败、故障资源删除和入口新鲜结果验证。
- Linux 下执行不跳过用例的全部 Go 测试，并启用 PostgreSQL 集成测试。Windows 的既有队列计时用例可能得到零耗时而失败，相关队列实现未修改，Linux 全量测试通过。
- 原更新脚本的八项回归及探针构建校验。修复这些脚本测试在 root 下的隔离问题：服务文件限定在各自临时目录，默认禁用真实 systemctl，验证 systemd 的用例显式使用模拟命令。此修复仅涉及测试，不更改生产更新脚本。

上述验证使用代表性旧数据和测试服务器，不是生产数据库副本或生产规模压测。升级兼容性已覆盖代码和测试能够验证的范围，生产备份、分步探针更新及升级后核对仍需执行。
