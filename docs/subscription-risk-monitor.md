# 订阅风险监控

入口：订阅中心 → 风险监控。复用 Go 订阅防护中间件写入的 `v2_subscribe_guard_event`，不安装 Python、不读取 Nginx 日志、不修改反代或订阅响应。

## 生效与兼容

更新后可直接查询保留的最近 24 小时请求。防护模式为关闭时仍记录并可评分；`SUBSCRIBE_GUARD_FORCE_OFF=1`、防护初始化失败或记录队列丢弃时，数据可能不完整。页面展示本进程丢弃计数。历史没有记录的数据无法补回。

评分在管理员查询时计算，窗口为 `(查询时间 - 24h, 查询时间]`。不在订阅响应链路增加查询，不新增请求日志表，不改变既有黑白名单、限流、账号及订阅。IP 情报使用独立缓存表，不存 Token 或邮箱。查询最多执行 5 秒；失败显示错误，不用空列表冒充成功。

窗口外的请求不会出现在实时风险列表，原始日志按原保留期清理。请求范围包括订阅拉取及节点列表、客户端配置等入口；`user_servers` 表示用户节点列表接口访问，不代表拉取了订阅。该列表中的主体数也不等于订阅用户人数。

后台扫描、快照写入及管理员查询与业务共用数据库连接池，会增加数据库和磁盘开销，不属于资源完全隔离的系统。可选 IP 情报在核心统计完成后补充，读取最多等待 250 毫秒；情报超时保留已查询成功的核心统计，标记情报暂不可用。当前没有生产规模压测结论。

有 Token 的请求按 HMAC 指纹汇总，支持原有全部订阅与入口路径；无 Token 的登录态入口按用户独立汇总。无法识别 Token 或用户的请求仍在请求日志中，不混成一个“用户”。同一账号的不同 Token 不混算；这里不是永久 Token 变更档案，历史仅限日志保留期。

搜索 ID、邮箱、完整 IP 或完整 Token 指纹时先计算完整主体指标再筛选；分页在评分和排序后执行。详情显示最近 24 小时的最新 100 条请求。

## 评分

参考 `v2board-subscription-monitor-share-1.9.1` 的多信号评分逻辑，最高 100 分：

| 指标 | 阈值与加分 |
| --- | --- |
| 1 小时请求数 | ≤3：0；4–6：10；7–10：20；>10：35 |
| 24 小时 IP 数 | ≤2：0；3–4：10；5–8：20；>8：35 |
| 24 小时 UA 变化次数 | ≤1：0；2–3：10；>3：20 |
| 最近请求空 UA / 脚本 UA | 15 / 10，互斥；复用现有脚本识别 |
| 最近请求未被防护拦截的 4xx | 12 |
| 24 小时未被防护拦截的 4xx ≥3 | 10 |
| 10 分钟 IP 数 ≥3 | 15 |
| 30 分钟 IP 数 ≥5 | 15 |
| 24 小时 ASN 数 | ≤2：0；3：10；4–5：20；>5：30 |
| 24 小时国家数 | ≤1：0；2：10；3：25；>3：40 |
| 10 分钟跨多个国家及 ASN | 30 |
| 30 分钟跨国家 | 20，与上一条互斥 |
| 最近 IP 有 IDC 信号 / 代理信号 | 各 10，必须是未过期且明确查询成功的结果 |

等级：0–19 低、20–39 轻度、40–59 中度、60–79 高、80–100 严重。
80 分以上且满足 24 小时 IP ≥5、1 小时请求 ≥7、10 分钟 IP ≥3、24 小时 ASN ≥3、10 分钟跨多个国家及 ASN 任一条件，标记建议人工复核。

UA 变化按请求时间和日志 ID 排序，相邻不同 UA 计一次；白名单请求及其相邻切换不计 UA 加分。空 IP 不计入 IP 数量。5xx 作为服务故障单独展示，防护自身的 403/429 不参与异常响应加分，防止评分反馈放大。

## 处理方式与范围

分数只用于人工判断，不自动限制账号或 Token。详情的“限制此 Token”复用原有快捷规则确认、有效期、配置版本冲突检查和审计。只有既有模式为正式拦截时才执行限制。

后台每分钟评估一次最近 24 小时行为，将 60 分及以上结果保存为独立历史快照，保留 30 天。同一对象、同一小时、同一分数去重，已保存的评分、原因、IP 情报和用户信息不被后续请求覆盖。属于定期采样，不能保证捕获评估间隔内的短暂高分；不回填声称为历史访问时刻的评分。采样定时任务使用数据库租期避免多进程重复运行。

“高风险历史与复核”支持用户 ID、邮箱、IP、完整 Token 指纹及状态筛选。待复核记录可标记已处理或误报，必须填写说明，保存管理员 ID、处理时间及版本；已处理记录不可重复覆盖。误报决定启用 24 小时复核冷却，匹配同一主体、IP、UA、国家/ASN、总分及完整评分原因（含具体计数与分值，顺序不敏感）。匹配的后续快照以及最近 24 小时已生成的匹配待复核记录标为“误报冷却记录”，保留快照及依据的误报记录 ID；不冒充管理员逐条审核，也不延长原冷却时间。来源、原因或分数变化不匹配冷却；到期后新的快照恢复待复核。普通“已处理”不启用冷却。该操作不封禁、解封或改变实时评分、原拦截规则。原始请求日志清理后，快照仍保存至自身保留期结束。

不移植 Telegram 提醒、超时自动封禁、独立审核队列或 Nginx map 封禁。IP 新旧判断在日志清理后无法保证完整，故不据此加分。

## IP 情报

与原监控使用相同来源：`https://ipwho.is/{ip}?lang=zh-CN` 提供国家、ASN、运营商，`http://ip-api.com/json/{ip}` 提供 hosting / proxy / mobile。免费 ip-api 接口不支持 HTTPS，因此其结果仅作为低置信度参考，HTTP 传输可能被篡改；不得据此自动封禁。proxy 是代理/VPN/Tor 的综合信号，不能确认具体代理协议或证明用户正在使用 VPN。

仅向来源发送规范化公网 IP 和固定字段参数，不发送 Token、邮箱、UA、订阅 URL、APP_KEY。私网、回环、共享地址、文档地址和保留网段不会出站查询。不接受请求头或管理员输入指定查询 URL。限制响应 64 KiB、单来源 5 秒超时，拒绝跳转，核对返回 IP；缺少字段标记未知，false 仅代表来源未检出。

服务内独立协程每分钟从最近 24 小时已保存日志补入 IP，后台每 3 秒最多查询一个 IP；数据库统一限速和独立的 60 秒任务租期支持多进程去重。手动重试跳过锁定、执行中及已排队的记录，不重置执行租期；每次领取增加任务版本，过期任务的迟到结果不能覆盖新任务结果。成功缓存 24 小时，失败或部分成功 1 小时后重试；429 和连接失败暂停外部查询至少 60 秒。数据库任务异常不阻塞订阅，也不影响原日志写入。30 天没有访问的缓存清理。

自动新增 `v2_subscribe_ip_intelligence`、`v2_subscribe_ip_lookup_rate`、`v2_subscribe_monitor_control` 和 `v2_subscribe_risk_history`，无需配置 Key。可选表在独立后台初始化，失败后每分钟重试；不会让原订阅防护、限流、请求记录及基础风险查询停用。可选表运行期间丢失或权限异常时，风险查询退回不含情报的统计；日志和用户详情的缓存读取也不决定主查询是否成功。

启动后逐步补齐旧日志中的 IP，不瞬间并发全量查询。“监控运行状态”显示查询开关、缓存数、待查/过期数、失败数、最近查询、最近历史评估及冷却时间。查询开关持久化并校验配置版本，仅控制外部 IP 查询，不控制统计、评分或原拦截规则；正在进行的请求可完成。“重试失败查询”每次最多重新安排 500 个最近活跃且查询失败的 IP，遵守全局冷却和限速，不重新查询成功缓存。`SUBSCRIBE_IP_INTELLIGENCE_OFF=1` 强制停止后台外部查询，优先于后台开关；既有未过期缓存仍可展示，历史评估继续运行。

风险页面显示国家/ASN 覆盖数量、每个请求 IP 的标签、状态及查询时间。普通请求日志、用户详情、Top IP 和爬虫明细复用同一缓存及显示组件，只进行有超时限制的批量缓存读取，不在页面查询时访问外部服务。未知、过期数据不参加地理多样性和网络标签评分。实时页面情报是最近查询结果，不是访问时刻的历史归属；多 IP、多国家也可能来自正常的移动网络或漫游，仍需人工复核。

验证：`go test ./...`；设置隔离 PostgreSQL 测试库的 `SUBSCRIBE_GUARD_TEST_DSN` 后执行 `go test ./internal/subscribeguard -run TestPostgresUpgradeAndGuardLifecycle -count=1`。前端 `npm run check`、`npm run build`。
