## 订阅中心

菜单位于“内鬼管理”下面。入口合并为四个标签，后端接口与历史记录继续兼容：

| 标签 | 数据与操作 |
| --- | --- |
| 统计与防护 | 成功获取订阅的记录、用户 ID/邮箱及 UA 查询、当日低流量、连续 N 天每天低流量明细，以及防护策略和开关 |
| 请求与拦截记录 | 全部订阅请求的放行、业务失败、规则命中和实际拦截，用户详情与快捷规则 |
| 爬虫 UA 用户 | 脚本/爬虫类别触发用户及明细，白名单命中也可记录 |
| （统计与防护页内） | UA/IP 白黑名单、Token 黑名单、频率限制、空 UA 与爬虫 UA 拦截开关 |

成功订阅统计与全部请求统计不相加；两者口径与保留期不同。关闭防护仍记录请求，爬虫 UA 默认只记录；实际拦截需要防护模式为“正式拦截”，并开启对应开关。爬虫识别只覆盖常用于拉取订阅或入口信息的命令行、HTTP 客户端和明确爬虫标识，不包含 Postman、Node fetch、Axios、浏览器自动化等开发/测试工具。升级不会重置已有防护设置。

页面中的“成功订阅日志保留期”和“风控请求日志保留期”分别对应两张日志表，不能合并成一个值；前者用于成功订阅统计，后者用于防护事件和拦截记录。

旧地址 `/subscribe-access` 和 `/config/subscribe-guard` 都打开订阅中心的“统计与防护”页。统计与防护在同一页展示，切换到其他记录标签时保留未保存配置。

## 域名解析

支持 DNSPod 国际版 Token API，以及 DNSPod 中国版/国际版腾讯云 API 3.0。可查询域名与记录、添加/修改/删除记录、启用/停用记录，并设置线路、TTL、MX、权重等服务商支持的字段。

在“域名解析 → 账号设置”配置凭证，可先验证账号。凭证保存在 `config/admin.json`，Linux 下文件权限为 `0600`，配置采用原子替换和进程内互斥，避免与系统配置并发保存时互相覆盖。状态接口只返回掩码；DNS 管理接口需要管理员登录，并禁止缓存响应。环境变量覆盖凭证时页面会提示。

## 备用监控

默认打开“入口监控”标签，按当前地址配置自动生成去重后的入口列表。地址优先级与下发选择器一致：**内鬼管理规则 → 绑定的节点地址组规则 → 节点管理地址**。同一层规则先处理所有具体 ID，再处理 ID 范围；同类匹配按原规则顺序取第一个。高优先级覆盖的 ID 会从低优先级入口的归属范围中扣除。同一地址用于多个节点或规则时合并 ID 范围及来源。

每个入口提供“删除”，勾选后也可批量删除（单次最多 500 个）。删除仅停止入口监控，清除绑定探针及当前检测状态，并将该地址移入“已删除入口”；节点、地址规则、订阅下发和备用 IP 池均不改变。删除记录按规范化地址持久保存，刷新或重启不会自动加入；同一地址被多个节点使用时一起停止检测。探针已领到的检测可能完成，但旧结果不会重新建立状态。需要恢复时，切换“已删除入口”，点击“恢复配置”，重新选择探针并保存；旧检测结果和版本不能复用。此视图仍只显示当前启用且参与下发的地址，已失去实际下发来源的地址不会因删除记录而显示。

管理接口 `POST /dns-failover/dispatch-entries/delete` 接受严格 JSON `{"hosts":["entry.example"]}`，整批校验后在事务中删除。`GET /dns-failover/dispatch-entries` 默认不返回已删除地址，`include_deleted=true` 可同时查看；`PUT` 保存当前实际入口时恢复删除标记。以上入口接口使用当前数据库会话校验管理员身份。

只汇总节点管理中已启用（`show=1`）的节点及启用的地址规则。停用节点不贡献入口、来源或 ID 归属；只由停用节点贡献的入口也不再下发探测任务。多个节点共用一个入口时，只要仍有启用节点贡献该入口，就继续保留并按启用节点计算归属。监控开关关闭的候选入口仍可显示，供管理员配置和启用监控。

节点地址组或组内规则关闭后，其地址不会进入入口监控；启用但未绑定启用节点的地址组也不会单独贡献入口。关闭地址规则时按原下发机制回退到低优先级地址，因此仍实际参与下发的节点原地址会保留。即使节点本身启用，若原地址的全部 ID 归属都被高优先级规则覆盖，原地址也不会列出。以上开关或规则变化在入口列表刷新后体现，探针任务目录最多另有 5 秒缓存和探针拉取周期的延迟。

这里显示配置中的 ID 归属，不查询用户表，不检查账号状态、节点权限、UA、套餐或注册天数；范围包含尚未注册的 ID。节点管理中的条件地址会列出所有地址候选，不执行匹配条件，因此不是历史订阅日志中的实际领取人数。额外节点链接不列入入口；额外节点配置若替换了原管理节点，被替换的管理节点也不会作为该范围的入口出现。

在列表勾选一个或多个入口，点击“配置”或“批量配置”，设置自定义 `port`、探针、检测间隔和 TCP 超时，并开启监控。手动新增配置使用当前浏览器该管理员上次输入的入口检测端口，没有记录时才使用 443；编辑单个已有入口使用该入口已保存的端口。监控默认关闭。展开入口可查看完整 ID/范围、配置来源，以及各探针的结果、延迟、解析 IP、错误和上报时间。任一探针报告失败即显示异常；缺少新鲜结果时显示等待或部分探针无数据。每 15 秒刷新入口与状态。

此功能只做入口 TCP 连通性监控，不触发 DNS 切换，不改变节点下发配置。修改监控配置会清除旧状态，并用配置版本拒绝旧端口的排队结果；探针离线或结果过期不显示为正常，撤销和重新连接探针也会清除旧监控状态。入口从地址配置消失后不再下发探测任务；原监控配置会保留，地址恢复时重新出现。

### 超时自动二分

备用监控的“故障转移”标签（位于“入口监控”右侧）提供自动二分设置，默认关闭。只对已绑定探针且启用监控、仍在实际下发、有效归属恰好为一个至少含两个 ID 的范围且不混有具体 ID 的入口生效。某一在线启用探针须持续上报 `timeout` 满 10 分钟，样本连续且新鲜、版本和会话一致，并且同一探针当前还能正常检测至少一个其他实际入口。恢复、非超时错误、明显上报断档、历史写入失败、配置/会话改变均不能当成连续超时；打开开关或保存频率后重新累计 10 分钟。

频率使用滚动窗口，默认同一根分组整棵树每 20 分钟最多成功一次，全局每 60 分钟最多成功三次。两个窗口可配置为 1–10080 分钟，全局次数可配置为 1–100。每个分组具有数据库分组编号，首次根分组保存自身编号；两半及更深后代分别取得新分组编号，同时继承不变的根分组编号和父分组编号。IP、ID 范围和名称只是快照，不作为限额键。某个后代成功二分后，兄弟组及所有同根后代都要等待新的单入口窗口。一次成功二分领取两个 IP，计一次；等待条件或整批回滚不计次数。成功记录和分组关系持久保存，重启、开关切换、频率调整不会清空额度。

后台每 30 秒检查。从备用池选择两个不同、同检测端口、健康且无地址配置引用的 IP；不接管已有入口监控或已删除监控的地址。仍沿用备用池“全部在线启用探针均有新鲜结果、连续成功至少两次”的判定。写入前在事务内再次核实健康、引用、当前规则和限额；不足两个则一个也不领取。按 ID 数值区间均分（奇数时前半多一个），两半都替换为新 IP，子入口继承原探针、检测端口、间隔和超时，并从无结果状态开始测活；不会继承父组的超时时长。原入口监控停用，历史保留。节点订阅端口不变，新地址在客户端下次刷新订阅时生效。

自动生成的子入口在当前检测配置和探针会话中必须先有成功记录，再连续超时满十分钟，才能再次二分；从未正常的新入口不会持续消耗备用 IP。修改端口、会话或地址后，旧配置的成功记录不能解锁新一轮；调整父子关系也不能绕过此保护。真实探针使用纳秒时间戳序号，校验其严格递增及相邻检测完成时间、服务器接收时间的间隔，不要求逐次加一；最大间隔为“检测间隔＋向上取整的 TCP 超时秒数＋5 秒调度余量”，超出则等待新证据，连续整数序号仍兼容。新入口使用数据库中来源入口的检测端口，不读取浏览器偏好，不回退为 443；后续修改子入口端口后，其后代继承修改后的值。

修改沿用现有三层地址规则：简单内鬼范围拆为两条内鬼规则，节点地址范围在同组内拆分并保留顺序，节点管理兜底范围通过绑定的节点地址规则承接。只自动修改来源为单一地址、单一明确范围、无额外节点的可核实规则；来源范围与有效归属不一致、条件地址、停用绑定组或优先级冲突等复杂情况跳过，并显示原因。事务提交前重新计算完整下发目录，确认只有故障范围变成指定的两半，其他入口归属不变；否则连同新监控、分组及备用 IP 使用一起回滚。设置行锁、容量锁与成功记录在同一事务内防止兄弟组、多探针或多次检查重复执行及超过全局额度。

设置区展示最近 50 条操作、当前分组和根分组编号、触发探针、等待/取消原因以及两半 ID 范围与 IP。等待条件会在后续检查中重新核实；恢复、停用、删除或会话变化取消旧等待。关闭功能只停止后续动作，不撤销已经完成的下发规则。新增表为 `v2_dispatch_auto_split_settings`、`v2_dispatch_auto_split_group`、`v2_dispatch_auto_split_operation`，无须升级已支持入口监控的探针。

“故障转移”中展示当前分组并提供编辑；每条已完成二分记录也可同时编辑两个子分组。父分组可改为已有分组或空（独立根分组），不能指向自身或后代；整棵子树同步根编号。新根继承原家族和目标家族较新的成功时间，移动、拆出或合并关系不能重置单入口冷却；全局成功记录及历史二分快照不修改。当前仍启用监控的分组可编辑单个 ID 范围和 IP/域名，已完成二分的旧入口只编辑关系，其实际范围与地址应在当前子分组中修改。

分组编辑使用管理员接口 `PUT /dns-failover/dispatch-auto-split/groups`，一次原子保存 1–100 组，携带分组修订号防止旧表单覆盖。支持同一次保存调整相邻两半边界；重新投影三层规则，校验各新范围完整下发、地址独立、所选范围以外归属不变。复杂来源、已被其他规则改变的分组、重叠冲突或已有监控地址占用时整批回滚。修改范围或地址会更新原地址规则和监控地址，递增监控版本与会话、清除旧状态；探针绑定、检测策略和节点下发端口不变。等待操作取消后重新核实；已完成历史及限额时间不受编辑影响。新增 `v2_dispatch_auto_split_cooldown` 持久保存迁移后的冷却，`v2_dispatch_auto_split_edit` 保存修改前后分组快照；原分组表增量添加 `revision`。

“当前分组”的监控状态与“入口监控”共用组件及 `dispatch-entries` 的实时探针数据，以监控编号和当前地址匹配。状态口径统一为未启用、正常、异常、部分探针无新鲜数据、等待测活 / 数据过期、已删除；启用开关本身不代表检测正常。仍启用但已不在实际下发目录的旧分组显示“未参与当前下发”，状态读取失败时显示失败提示；两处均每 15 秒刷新。

### 备用 IP 池

支持批量添加 IPv4、IPv6，按 `IP＋port` 去重；同一 IP 的多个端口可分别建资源、分别测活。每行支持 `IP [端口] [名称]`、`IPv4:port [名称]`、`[IPv6]:port [名称]`，省略端口使用批量表单默认值；默认值记住当前浏览器该管理员上次输入的备用池端口，没有记录时为 443，与入口检测的输入记忆独立。每次最多 500 行，重复或无效资源使整批回滚。编辑可调整名称、port、启用状态、间隔、超时和排序；IP 固定，若需换 IP 则新增资源。编辑及“重新测活”清除旧结果、增加任务版本和会话，旧端口及排队结果不能恢复健康状态。

全部启用探针持续测活，在线判定为最近 90 秒有心跳。至少有一个在线探针，且所有在线启用探针都具有新鲜结果、连续成功至少 2 次，并且没有地址配置引用，才标为可用；离线探针不参与通过条件。任一在线探针有新鲜失败则不可用。新鲜窗口按两轮“间隔＋超时”计算，探针心跳独立检查，长间隔不会因硬编码 90 秒结果上限而无法累计成功。这里的成功仅代表该端口 TCP 可连接，不能证明代理协议、认证、转发或 UDP 可用。

展开可分别查看配置引用、当前下发 ID / 范围、来源及逐探针状态。配置引用扫描内鬼规则、节点地址规则、八类管理节点的字面 IP，包含停用配置并拆出条件地址候选，不含额外节点，也不解析域名追踪间接引用。引用是保守的地址预留，按 IP 判断，不因端口不同而解除引用；当前下发归属沿用现有三层优先级口径。有引用的资源不能删除；所选删除中有引用则整批取消。删除只清理备用资源与测活状态，不修改地址配置。

可复制健康未占用资源去重后的纯 IP（每行一个，不含检测端口），支持“删除故障 IP”，确认后重新获取状态，仅清理故障且无配置引用的记录，范围覆盖整个池，不受搜索和勾选影响；同一 IP 不同端口独立判断。复制支持 HTTP 后台；浏览器阻止自动复制时显示可手动复制的文本。备用池 port 仅用于探针检测，不改变节点下发端口。“故障转移”和“谁是卧底”在相应开关启用且满足条件时，从池中领取同检测端口的健康未占用 IP；池本身不独立触发入口改写。

### 近期检测

入口监控和备用 IP 池的主动检测按钮已移除。“近期检测”现在默认显示探针已接受的持续检测结果；“诊断日志”查看同一份检测明细（结果、延迟、解析 IP、错误和归属快照），“事件”查看逐目标、逐探针的故障和恢复变化。可按来源、完整地址、检测端口、探针 ID、结果、事件类型和时间筛选，每页 50 条，每 10 秒刷新。诊断日志和事件的来源选择器仍可切换到原有 DNS 切换记录。

新历史独立存储于 `v2_dispatch_history`，检测明细保留 24 小时，事件保留 3 天，每小时分批清理过期数据。历史不依赖配置或探针的外键，删除入口、备用资源或探针、重新测活、编辑端口和服务重启不会清除已记录的历史；重复、乱序或已失效的上报不记录为新样本。记录保存当时的 host、检测端口、探针名称及配置 ID 归属快照，目录缓存最多 5 秒；归属计算失败时明确标记未知，不伪装成无人使用。此快照仍沿用三层地址优先级，不额外检查账号状态、权限和地址匹配条件。

首次有效失败或正常转失败生成故障事件；重复失败不重复生成。入口同一探针恢复成功即记录恢复，备用池须连续成功 2 次。配置版本或探针会话改变、前一结果过期时不推断恢复事件；探针离线及数据过期仍在实时状态页展示。这些事件描述对应探针的观测，不代表整个入口不可用，不触发 DNS 修改或通知。DNS 切换仍使用原有阈值、日志、事件和通知机制。

历史批量写入使用保存点、短锁等待和 SQL 超时；历史表写入失败时回滚历史部分，继续提交实时检测结果，并记录服务错误、在查询页面显示历史可能不完整。修复前未保存的检测历史无法补回；本次保存历史使用现有持续上报接口，已经支持入口监控的探针无需为历史功能再次升级。

旧版主动检测任务移至“近期检测”中的折叠区，仍可查看和清理；下文的轮次、完成状态和 7 天保留规则只适用于这些旧任务。历史任务通过独立目标下发，每个目标/探针只记录第一份有效结果，不覆盖持续监控状态。

每轮保存发起时的 host、port、探针名称和配置 ID 归属快照（具体 ID、范围、来源）。之后配置改变、删除备用资源或删除探针，不会改写该轮历史；快照代表发起时配置投影，不是账号权限或历史订阅领取人数。收齐结果标为完成；含失败结果也可以完成。5 分钟未收齐则超时，未返回的探针对应行仍可查看。旧会话、旧任务版本、重复及乱序上报不会覆盖已记录结果。探针重新连接会重置未完成目标的会话，已经记录的历史保留。

记录默认保留 7 天，列表每页 20 轮，明细每页 100 份，可翻页查看完整结果；最多同时 10 轮，每次最多 500 个目标和 10000 份预期结果。后台查询及探针拉任务时更新超时状态、分批清理过期记录。手动清理只删除已经结束的任务。新页面在激活时自动刷新：池 10 秒，近期任务/展开结果 5 秒。

已有探针需要升级：先更新面板并构建探针文件，再在“探针”标签查看原探针的安装命令，在探针服务器重新执行以安装新版二进制。只更新面板时，旧探针仍执行原 DNS 任务，新监控需要本次新版探针。

入口与备用池复用探针身份，使用独立的 `/api/v1/probe/monitor-tasks`、`/api/v1/probe/monitor-results` 接口、请求循环及重试队列；原 `/tasks`、`/results` 只负责 DNS。新监控目录或结果写入失败不会阻断旧 DNS 请求。上个测试版本探针发送的混合批次中，DNS 结果正常处理，负数结果明确计入跳过，不再写入新监控；升级探针后恢复新监控。

每枚探针最多启用 1000 个新增目标（入口及备用池合计，备用池分配给全部启用探针）。保存配置时通过事务及锁检查预算，超限整批回滚；允许停用资源以减少已有超限配置。任务响应另有 768 KiB 上限，超限明确报错，不静默截断；旧 DNS 任务不计入新增目标预算。新版探针按参考项目的方式，为每个入口与备用池目标启动独立检测任务，不设置跨目标 TCP 并发名额，不再使用此前的串行或 64 并发限制；不同探针各自独立，原 DNS 检测使用独立调度。待上报结果队列与通道有界；故障期间保留顺序并施加背压，避免无限积压。任务目录缓存 5 秒，配置移除后最长等待缓存与探针刷新周期才停止检测。

检测间隔表示同一目标上次检测完成并送入结果通道后，至少等待多久再开始下一次检测；同一目标不会重叠执行周期检测。不同目标可以同时连接，超时分别计算。新鲜度规则保持不变，结果过期时显示等待/过期并停止标记可用。1000 是任务容量保护上限，不是固定 TCP 并发数或实时性承诺；实际并发取决于目标数量、连接耗时、检测间隔及结果队列背压。

探针每次拉新增任务仅同步自身的备用池绑定，不重复计算全部探针的笛卡尔积；备用池结果写入不再使用全局结果锁，历史任务使用各自任务行锁协调。原探针心跳不依赖新表初始化；初始化失败记录日志，原 DNS 继续工作。新监控重置失败由保存点回滚，旧心跳正常提交，新监控会暂停接收结果直到重置成功。每次面板进程重新初始化时，清空新增监控的当前测活状态并更新会话，等待重新测活；历史已完成结果和用户配置保留。

“删除故障 IP”调用独立服务端接口 `/dispatch-pool/delete-faulty`。后台在同一事务中锁定候选资源和测活结果，重新判断故障、结果新鲜度、启用和在线状态；已恢复、检测中、停用、离线或有配置引用的资源跳过。引用表在短事务中加共享锁，防止引用查询后又并发写入地址引用。删除事务不锁原探针行，不阻塞旧 DNS 心跳/上报。获取锁最多等待 2 秒，忙时整批回滚重试。响应分别返回 deleted 和 skipped 数量；每次最多 500 个候选。

主动检测的创建 API 已关闭（返回 405），已有历史任务仍可查看与清理。新版探针依据旧任务接口的能力标志启用新通道；回滚到 b21c39c 后，新通道停止，遗留的新增结果不会混入 DNS 队列；404/405 响应会清除不再支持的新增批次。上线仍建议先面板、后单枚探针验证，再逐步升级；回退时同步恢复前端、后端及探针下载文件，重启探针以立即清理内存任务。原 DNS 规则可能需要重新预热，应观察上报和结果新鲜度。

原有主备功能位于“DNS 切换规则”标签，使用流程如下：

1. 在“探针”标签设置 HTTPS 接入地址，如 `https://probe.example.com`，该地址需转发到当前 Go 服务。
2. 创建探针，在需要观察连通性的 Linux 服务器上执行页面生成的安装命令。支持 amd64/arm64，下载校验 SHA256，密钥配置权限为 `0600`。探针通过专用 Bearer Token 鉴权，撤销后立即拒绝上报。
3. 新建规则并选择 DNSPod 域名、已有 A/AAAA/CNAME 记录和探针。按优先级填写主备目标与 TCP 探测端口。首个启用目标应与当前 DNS 解析一致。
4. 核对配置后显式启用规则。新规则默认停用，自动回切默认关闭；启用后才能开始该规则的探测。至少三批有效上报完成预热，过期结果不参与决策。
5. 在“监控详情、诊断日志、事件”中查看探针状态、连续失败/成功次数、切换与重试原因。可手动切换，也可单独启用恢复后回切。

多探针按阈值共同判断，只有单个可用探针时采用更高阈值。所有探针离线、数据不足、探针意见不一致或没有健康备用目标时不会盲目切换；冷却期限制反复切换。修改 DNS 与数据库状态通过持久任务、锁、重试和补偿协调。重新启用探针会清除旧结果并重新预热。

诊断日志、探针上报去重记录及已通知事件保留三天，每小时分批清理；待通知事件保留重试。清理任务独立运行，不改变原订阅和流量记录的保留策略。

Telegram 使用现有机器人设置和已绑定的管理员；发送失败保留事件等待重试。通知采用至少一次投递，发送成功但回写数据库失败时可能重复通知。未配置机器人或没有接收人不会标记为已送达。DNSPod凭证、探针Token均应按服务器配置密钥保护；探针Token为了再次生成安装命令会以明文保存在数据库，仅管理员接口可读取。

## 老项目升级

DNS 功能表为 `v2_dns_*`，入口监控使用 `v2_dispatch_monitor`、`v2_dispatch_monitor_probe`、`v2_dispatch_monitor_state`，备用池与主动检测新增 `v2_dispatch_check_run`、`v2_dispatch_check_target`、`v2_dispatch_check_binding`，持续检测历史新增独立的 `v2_dispatch_history`。按需重复执行初始化，不改用户、订阅 Token、套餐、流量及既有地址规则。初始化失败时后续请求会重试；原订阅服务继续启动。没有创建并启用 DNS 切换规则时，不会改 DNS。

正常更新仍使用 `./scripts/appctl update`。它会额外构建 `storage/probe/forest-probe-linux-amd64`、`forest-probe-linux-arm64` 及校验文件；也可单独执行 `./scripts/appctl build-probe`。该目录不入 Git。前端构建产物随本次代码一同更新。

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| `PROBE_STORAGE_DIR` | 探针下载文件目录，默认 `../storage/probe`，相对 Go 服务工作目录 |
| `PROBE_TRUSTED_PROXY_CIDRS` | 允许读取转发 IP 的代理网段。默认含回环与私网段；部署时应收紧到实际代理，如 `127.0.0.0/8,::1/128` |

升级前保留数据库、`.env.go` 和 `config/admin.json` 备份。回滚前先停用 DNS 规则并等待切换任务完成；回滚代码不会撤回已生效的公网 DNS 修改。新增表可以保留，旧版不读取它们。

## 验证

- Linux `go test ./...`、`go vet ./...` 均通过；DNSPod API、决策、补偿、过期数据、重复上报、探针鉴权和通知失败均有测试。
- 独立 PostgreSQL 数据库验证重复升级、旧用户/订阅统计保留、规则和探针生命周期、去重、撤销、重新预热，以及历史清理保留待通知事件。
- 可设置独立测试库 URL `DNS_FAILOVER_TEST_DSN` 后运行 `go test ./internal/admin -run TestPostgresDNSUpgradeAndProbeLifecycle`；测试仅使用自行创建的临时 schema。
- `npm run check`、`npm run build`，以及使用模拟 API 数据的浏览器验收。
- `bash scripts/test-appctl-build-probe.sh` 与现有 appctl 更新脚本测试。

执行历史 appctl 测试时需隔离服务管理：设置 `SYSTEMCTL_BIN` 为不存在的临时路径，并将 `FOREST_SERVICE_FILE_PATH`、`LEGACY_FOREST_SERVICE_FILE_PATH` 指向测试目录，避免测试用的 `start/update` 操作真实服务；使用模拟 systemctl 的用例会自行覆盖这些值。

未使用真实 DNSPod 凭证修改公网记录；正式启用前仍需用专用测试域名完成外网探针、实际切换及 DNS 缓存/TTL 验证。
