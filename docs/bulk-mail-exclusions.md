# 群发邮件排除内鬼用户

用户管理的群发邮件自动排除内鬼管理中的用户，无需额外开关或维护第二份黑名单。管理员和员工的群发接口执行相同的排除逻辑；员工原有的用户权限范围保持不变。验证码、密码找回、工单回复等事务邮件不受影响。

## 匹配规则

- 读取全部内鬼规则，启用和停用的规则都参与群发排除。停用只影响节点下发。
- 指定用户 ID 和 ID 范围取并集，范围含两端。通过邮箱选中的用户已保存为用户 ID，修改邮箱不会解除排除。
- 同一用户命中多条规则只计一次，不展开大范围 ID。
- 发送弹窗显示当前筛选人数、排除人数、无地址人数和可发送人数。刷新人数不发送邮件。

## 发送流程

1. `POST /api/v1/{admin_path}/user/mailPreview` 接受与群发相同的 `filter`、`sort`、`sort_type`，返回 `data: {total, excluded, unavailable, eligible}`。员工使用 `/api/v1/staff/user/mailPreview`。预览和发送共用筛选解析：支持表单 `filter[0][key]` 等字段和 JSON `filter` 对象数组；格式错误时拒绝处理，避免忽略筛选后扩大收件范围。
2. 提交 `user/sendMail` 时重新筛选并排除，只有可发送用户进入原有邮件队列。没有可发送用户返回错误；成功入队仍返回 `data: true`，保持旧客户端兼容。
3. 每封邮件在限速等待结束后再次读取最新内鬼名单。新命中的用户跳过；入队时已排除的用户不会补回该批次。被删除或邮箱已变更的收件人也跳过。
4. 名单格式错误、数据库查询失败或无法复核收件人时停止后续发送。队列提交失败直接报错，不回退到同步发送。SMTP 单封失败保留原有的邮件日志并继续处理其他收件人。

预览为查询时的人数，成功入队不代表全部送达。实际尝试发送的邮件仍写入邮件日志；服务日志记录跳过的用户 ID、停止原因以及批次发送/失败/跳过/未处理数量，不记录内鬼规则内容。

## 升级和限制

无需新增配置或数据库迁移，复用现有内鬼规则表及其兼容初始化。前后端一起升级，内鬼名单为空时维持原有群发范围。应在群发队列空闲时更新：现有队列保存在进程内，重启不会续发未完成批次。

复查以 SMTP 调用前的最新查询为准；邮件已经交给 SMTP 后，新增规则无法撤回该邮件。停止的批次不自动重试，避免重复发送；根据日志核对后再安排新的批次。

验证使用模拟 SMTP，覆盖 ID/范围排除、名单变化、读取失败、队列失败、限速复查、邮箱变更、管理员/员工权限及旧版布尔响应。页面验收只调用预览，不向实际用户试发。
